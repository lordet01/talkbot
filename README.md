# 리듬이

말 거는 인형. **talkbot**은 그 안의 대화 엔진이다.

## 한 줄 정의

리듬이는 **듣고(STT) → 생각하고(LLM) → 말하는(TTS)** 루프로, 아이·보호자와 자연스럽게 대화하는 인형이다.

## 왜 만드는가

인형은 이미 “친구”처럼 보이지만, 대개 버튼·녹음 재생에 그친다.  
리듬이는 그 자리에 **실시간 대화**를 넣어, 인형과 실제로 이야기 나누는 경험을 만든다.

talkbot의 역할은 캐릭터 UI가 아니라 **그 대화를 가능하게 하는 엔진**이다.

## 엔진 (talkbot)

```
마이크  →  VAD  →  STT  →  LLM  →  TTS  →  스피커
(듣다)     (말할 때)  (글자)  (답)   (목소리)  (들리게)
```

| 단계 | 역할 | 리듬이에서의 의미 |
|------|------|-------------------|
| **VAD** | 말 시작·끝을 가른다 | 버튼 없이 “말하면 알아듣는다” |
| **STT** | 음성을 텍스트로 | 아이의 말·섞인 말을 이해의 재료로 |
| **LLM** | 의미 파악 + 캐릭터 답변 | 리듬이답게, 짧게, 따뜻하게 |
| **TTS** | 텍스트를 목소리로 | 인형에서 나는 말소리 |

자연스러움은 모델 하나가 아니라 **루프 전체의 타이밍·끊김·말투**에서 나온다.

## 제품과 엔진의 관계

| | 리듬이 | talkbot |
|--|--------|---------|
| 무엇인가 | 대화하는 인형(제품·캐릭터) | STT–LLM–TTS 대화 엔진 |
| 사용자가 느끼는 것 | “인형이 나한테 말해 줘” | (보이지 않음) |
| 개발이 다루는 것 | 페르소나, 안전, UX | 지연, 인식, 재생, 안정성 |

리듬이 = **캐릭터 + 몸체 + 안전 규칙**  
talkbot = **듣고 답하고 말하는 파이프라인**

## 대화가 “자연스럽다”는 기준

1. **말하면 알아듣는다** — 웨이크워드·버튼에만 의존하지 않는다.
2. **끊기지 않는다** — 말 끝이 잘리지 않고, 답도 너무 늦지 않다.
3. **리듬이답게 말한다** — 짧고, 구어체이며, 캐릭터에서 벗어나지 않는다.
4. **이어서 이야기한다** — 직전 맥락을 잠시 기억한다.
5. **실패해도 부드럽다** — 못 알아들어도 침묵·에러음 대신 다시 듣는다.

## 현재 프로토타입 (하드웨어)

- **보드:** Seeed ReSpeaker Lite + XIAO ESP32-S3  
- **입력:** I2S 마이크 (16 kHz)  
- **출력:** I2S 스피커  
- **연결:** Wi-Fi → 클라우드 API  

검증 스케치: `arduino/05_groq_voice_chat`  
(마이크 → VAD → Groq Whisper → Chat → Orpheus TTS → 스피커)

보호자 제어판(QR/PWA): [`control-panel/`](control-panel/) — Cloudflare에 올리고 인형 바닥 QR로 즉시 연다.  
`./scripts/deploy_control_panel.sh` → `.env`의 `CONTROL_PANEL_URL` 설정 → `./scripts/sync_secrets.sh`

## Swift 스마트폰 앱

[`ios/`](ios/)에 iPhone/iPad용 **디노 앱**을 추가했습니다. 가로 스탠드에서 실시간 음성 대화, 끼어들기, 연령별 어린이 대화 지침, 카메라 기반 눈맞춤과 표정을 제공합니다. 기존 ESP32 없이 휴대폰 자체로 동작합니다.

`ios/Talkbot.xcodeproj`를 Xcode에서 열어 실행합니다. 보호자 설정에서 음성 API 연결 정보를 입력합니다. **1초 응답은 목표이며 네트워크·API에 따른 모든 턴 보장은 아닙니다.** 앱에서 실제 렌더 기준 지연 추정치와 초과 횟수를 확인할 수 있습니다. 설치·구조·검증은 [`ios/README.md`](ios/README.md)를 참고하세요.

## 설계 원칙

- **엔진 먼저, 장식 나중** — 대화 루프가 안정되기 전에 기능을 늘리지 않는다.
- **짧게 말한다** — TTS·체감 지연을 위해 답은 1–2문장.
- **임베디드에 맞게** — 온디바이스는 듣기·재생·타이밍, 무거운 인식·생성은 클라우드.
- **캐릭터는 프롬프트로** — 이름·말투·금지 주제는 LLM 시스템 규칙으로 고정한다.
- **아이 앞의 제품** — 유해·과도한 답변을 막고, 보호자가 이해할 수 있는 동작을 유지한다.

## 하지 않는 것 (지금은)

- 범용 스마트폰 비서 대체
- 긴 에세이·코드·검색 에이전트
- ESP32 인형 자체의 화면 UI (Swift 앱은 별도의 화면 캐릭터를 제공)

## 성공의 모습

아이가 인형에게 말하고, 잠깐 뒤 인형이 **알아들은 듯한 짧은 말**로 받아 준다.  
그 왕복이 어색하지 않게 몇 번 이어지면, talkbot 엔진은 제 역할을 한 것이다.
